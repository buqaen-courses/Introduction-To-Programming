# جلسه ۱۹: کار با فایل‌ها، خواندن و نوشتن فایل‌های متنی

## مرور جلسه

هرچه تا اینجا نوشتید به‌محض بسته شدن خودش را فراموش می‌کند. فایل‌ها راهی هستند که برنامه‌ها داده را نگه دارند: خواندن یک تنظیم، نوشتن یک لاگ، ذخیره یک کارنامه، به یاد داشتن بالاترین امتیاز. این جلسه فراخوانی `open()`، سه حالت فایلی که لازم دارید، دستور `with` که تضمین می‌کند فایل بسته شود، و روش پردازش محتوای فایل خط‌به‌خط را پوشش می‌دهد.

## اهداف یادگیری کلیدی

در پایان این جلسه می‌توانید:

- **توضیح دهید** مسیر فایل چیست و مسیرها چطور بین سیستم‌های مختلف فرق دارند
- **باز کنید** فایل‌ها در حالت خواندن، نوشتن و افزودن
- **به‌کار ببرید** `with` تا فایل همیشه بسته شود
- **بخوانید** یک فایل یکجا، خط‌به‌خط، یا در یک فهرست
- **بنویسید** و **اضافه کنید** به یک فایل متنی
- **مدیریت کنید** `FileNotFoundError` و دیگر خطاهای فایل را به‌صورت شکیسته

## سه حالتی که لازم دارید

```
    MODE     MEANING                    IF FILE EXISTS
    ----     -------                    ---------------
    'r'      read (default)             read from the start
    'w'      write                      ERASE, then write
    'a'      append                     write to the end

    ALWAYS pair with 'with'. Always.
```

تله `w`: فایل را خالی می‌کند. اگر فایل موجودی را در حالت نوشتن باز کنید، محتویاتش پیش از آنکه حتی یک نویسه بنویسید از بین رفته است. این رفتار بیشتر از هر رفتار دیگری در پایتون تکالیف دانشجوها را نابود کرده است.

## همیشه از `with` استفاده کنید

```python
with open("data.txt", "r") as f:
    content = f.read()
# f اینجا به‌طور خودکار بسته می‌شود، حتی اگر read() خطا داده باشد
```

بلوک `with` فایل را در پایان بلوک می‌بندد، چه به‌صورت عادی تمام شده باشد چه با استثنا. به این می‌گویند context manager، و یک دسته کامل از باگ‌ها را حذف می‌کند:

```python
# این کار را نکنید
f = open("data.txt", "r")
content = f.read()
f.close()        # فقط وقتی اجرا می‌شود که بالا خطا نداده باشد
```

اگر `read()` شکست بخورد، آن خط آخر هرگز اجرا نمی‌شود و فایل باز می‌ماند.

## خواندن

```python
# کل فایل به‌صورت یک رشته
content = f.read()

# یک خط در هر بار - روش کم‌مصرف حافظه
for line in f:
    print(line, end="")      # end="" از خط جدید دوم جلوگیری می‌کند

# همه خطوط به‌صورت فهرست
lines = f.readlines()

# تعداد ثابتی نویسه
first_100 = f.read(100)
```

پیمایش مستقیم شیء فایل، به‌جای فراخوانی `readlines()`، برای فایل‌های بزرگ ترجیح دارد: حافظه ثابت مصرف می‌کند به‌جای اینکه همه‌چیز را یکجا بارگذاری کند.

## نوشتن

```python
with open("output.txt", "w") as f:
    f.write("first line\n")
    f.write("second line\n")

with open("output.txt", "a") as f:
    f.write("appended later\n")
```

آن `\n` نویسه خط جدید است. بدون آن همه‌چیز در یک خط می‌افتد. توجه کنید که `write()` تعداد نویسه‌های نوشته‌شده را برمی‌گرداند، نه متن را، پس ننویسید `f.write(f.write("x"))`.

## مسیرها

```python
open("notes.txt")                  # نسبت به پوشه جاری
open("data/scores.txt")            # زیرپوشه، اگر وجود داشته باشد
open("/home/user/notes.txt")       # مطلق، یونیکس
open("C:\\Users\\me\\notes.txt")   # مطلق، ویندوز
```

ویندوز از `\` استفاده می‌کند و یونیکس از `/`. ماژول‌های `pathlib` و `os.path.join()` پایتون اجازه می‌دهند یک عبارت مسیر بنویسید که روی هر دو کار کند:

```python
from pathlib import Path

p = Path("data") / "scores.txt"
if p.exists():
    print("found it")
```

## مفاهیم اصلی

- **`open(path, mode)`** نقطه ورود هر عملیات فایل است
- **`r` برای خواندن، `w` برای نوشتن و خالی کردن، `a` برای افزودن**
- **`w` محتوای موجود را از بین می‌برد** پیش از آنکه چیزی بنویسید
- **`with` بسته شدن را تضمین می‌کند**، حتی وقتی استثنا رخ دهد
- **`for line in f`** فایل را جریانی می‌خواند؛ `readlines()` همه را بارگذاری می‌کند
- **`\n`** خط جدیدی است که خودتان باید بنویسید
- **`pathlib.Path`** جداکننده مسیر را به‌شکل قابل‌حمل مدیریت می‌کند
- **`FileNotFoundError`** خطایی است که باید روی هر خواندنی انتظارش را داشته باشید

## اشتباهات رایج مبتدی

| اشتباه | پیامد |
|--------|-------|
| باز کردن با `w` وقتی قصد خواندن داشتید | فایل خالی می‌شود |
| فراموش کردن `with` | فایل در صورت خطای میانی باز می‌ماند |
| فراموش کردن `\n` در `write()` | همه خروجی در یک خط |
| استفاده از `read()` روی فایل بزرگ | کل فایل در حافظه بارگذاری می‌شود |
| فرض اینکه مسیر وجود دارد | `FileNotFoundError` |
| نوشتن سخت مسیر ویندوز | روی هر ماشین دیگری خراب می‌شود |
| استفاده از نتیجه `f.write(...)` به‌عنوان متن | آن یک عدد صحیح است |

## فعالیت‌های کارگاه

۱. **برنامه دفتر خاطرات.** یک یادداشت بپرسید و با یک خط تاریخ پیش از آن به فایل متنی اضافه کنید. سه بار اجرا کنید و فایل را ببینید.
۲. **شمارش کلمات، نسخه ۲.** فایلی با چند بند بنویسید، بعد بخوانید و تعداد خط، کلمه و نویسه را گزارش دهید. به‌صورت جریانی انجامش دهید، نه با `read()`.
۳. **کپی فایل.** یک فایل را بخوانید و محتویاتش را در فایل دیگری بنویسید، به‌طوری که تعداد نویسه‌ها هم‌خوان بماند.
۴. **تمرین فایل گم‌شده.** تلاش کنید فایلی را باز کنید که وجود ندارد. خطا را بگیرید، پیام دوستانه‌ای چاپ کنید، و به‌جای کرش تمیز خارج شوید.

## تکالیف

- **ساخت لاگ**: برنامه‌ای که زمان‌های ورود را به یک فایل لاگ اضافه می‌کند، هر بار در یک خط. چند بار اجرا کنید و رشد فایل را نشان دهید.
- **آمار فایل**: با داشتن یک فایل متنی، تعداد خط، کلمه و نویسه را چاپ کنید.
- **محافظ**: هر برنامه‌ای قبلی‌تان که فایل می‌نویسد را بردارید و با `os.path.exists()` بررسی اضافه کنید که پیش از بازنویسی هشدار بدهد.
- **تأمل**: یک بند کوتاه درباره اینکه چه زمانی برنامه‌های مبتنی بر فایل ابزار درست هستند و چه زمانی اضافه‌کاری‌اند.

## نکات کلیدی

- `w` فایل را خالی می‌کند. مهم‌ترین نکته این جلسه همین است.
- همیشه از `with` استفاده کنید. فایل را هرچه که هست می‌بندد.
- برای فایل بزریدار با `for line in f` جریانی بخوانید.
- `\n` خودش در `write()` ظاهر نمی‌شود.
- `FileNotFoundError` را مدیریت کنید. حالت خاص نیست، حالت پیش‌فرض است.
