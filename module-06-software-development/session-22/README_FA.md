# جلسه ۲۲: مرور، تثبیت و پروژه‌های پایانی

## مرور جلسه

آخرین جلسه. این یکی نحو تازه‌ای ندارد، چون هدف، نحو تازه نیست، بلکه بررسی این است که آیا ایده‌ها به‌اندازه کافی در دسترس شده‌اند که هر وقت لازم شد فراخوانی شوند. مسیر دوره را مرور می‌کنیم، می‌سنجیم که اکنون بدون کمک چه چیزی می‌توانید بسازید، و بیشتر وقت جلسه را روی پروژه خودتان می‌گذرانیم.

## اهداف یادگیری کلیدی

در پایان این دوره می‌توانید:

- **توضیح دهید** کامپیوتر چطور داده را از بیت تا کدگذاری متن نمایش می‌دهد
- **طراحی کنید** یک الگوریتم پیش از نوشتن کد، با IPO و FIDEO
- **بنویسید** کد پایتون با متغیر، کنترل جریان، مجموعه و تابع
- **مدیریت کنید** خطاها عمدی، نه تصادفی
- **سازماندهی کنید** یک برنامه بین چند فایل، و خواندن و نوشتن داده
- **شناسایی کنید** گام مشخص بعدی در یادگیری‌تان

## روی چه چیزی ساختید

دوره به‌عمد ترتیب داده شده بود. هر ماژول به پرسشی پاسخ داد که ماژول قبلی مطرح کرده بود:

```
    M1  کامپیوتر چطور کار می‌کند؟       CPU، حافظه، فرایند، سیستم‌عامل
        ↓
    M2  داده چطور ذخیره می‌شود؟         بیت، بایت، باینری، کدگذاری
        ↓
    M3  برنامه چه کاری باید بکند؟      IPO، FIDEO، شبه‌کد
        ↓
    M4  چطور در پایتون بگویم؟         نحو، انواع، کنترل جریان، مجموعه‌ها
        ↓
    M5  چطور نگهدارش‌پذیرش کنم؟        توابع، خطاها، فایل‌ها، ماژول‌ها
```

شما اول پایتون را یاد نگرفتید و امیدوار بودید مفاهیم بعداً برسند. شما اول یاد گرفتید کامپیوتر چیست، و پایتون بلافاصله معنی پیدا کرد. تفاوتی که این دوره برای ساختن طراحی شده بود همین است.

## جعبه‌ابزار شما

```
    CONCEPTS                      PYTHON
    --------                      ------
    binary, hex, encoding    →    str, bytes, .encode(), .decode()
    IPO model                 →    input, computation, print
    control structures        →    if / elif / else, while, for
    sequences                 →    list, tuple, dict, set
    algorithm                 →    def, parameters, return
    finite state              →    local variables, modules
    data persistence          →    open(), with, json
    error conditions          →    try / except / else / finally
    modular design            →    imports, __main__, project layout
```

اگر می‌توانید از «برنامه باید جمع اعداد یک فهرست را حساب کند» تا کد کارا بدون هیچ مراجعه‌ای بروید، این دوره کار خودش را کرده است.

## خودسنجی

این‌ها را بدون یادداشت امتحان کنید. پاسخ، نام یک مفهوم یا یک قطعه‌کد کوتاه است.

۱. چرا `range(5)` پنج مقدار تولید می‌کند که از صفر شروع می‌شود؟
۲. `input()` چه برمی‌گرداند، و پیش از حساب چه باید کرد؟
۳. وقتی هنگام پیمایش یک فهرست را تغییر می‌دهید، چه اشکالی پیش می‌آید؟
۴. چرا `x = my_list.sort()` مقدار `x` را `None` می‌گذارد؟
۵. تفاوت `except ValueError:` با `except` خام چیست؟
۶. حالت `w` با یک فایل موجود چه می‌کند؟
۷. چرا یک فایل به `if __name__ == "__main__":` نیاز دارد؟
۸. وقتی `s.find("x")` غایب باشد چه برمی‌گرداند، و چرا در `if` خطرناک است؟

اگر روی چند مورد مکث کردید، به‌جای رفتن به جلو، ماژولی را که در [overview.md](../../overview.md) نام برده شده دوباره مرور کنید.

## پروژه پایانی

چیزی انتخاب کنید که واقعاً دوست دارید وجود داشته باشد. شرط پیچیدگی نیست، شرط **تمام شدن** است: کارا، مستند، و تست‌شده روی داده‌ای که آخر لحظه نساخته‌اید.

ایده‌هایی که با مهارت‌های فعلی‌تان جور است:

```
    text analyser      شمارش کلمات، فراوانی، بلندترین کلمه، آمار خط‌به‌خط
    expense tracker    خواندن فایل، دسته‌بندی، خلاصه ماهانه
    quiz engine        پرسش‌ها در فایل، نمره‌دهی، مرور پاسخ‌های غلط
    log analyser       تجزیه لاگ، شمارش انواع خطا، شلوغ‌ترین ساعت
    contact book       افزودن، جست‌وجو، ویرایش، حذف، ذخیره در JSON
    number tool        تبدیل بین پایه‌ها، مثل ماژول ۲
```

هرچه انتخاب کردید، این خروجی‌ها را هدف بگیرید:

- [ ] بدون خطا روی ورودی‌هایی که خودتان ننوشته‌اید اجرا می‌شود
- [ ] توابعی که هرکدام یک کار می‌کنند، همراه با docstring
- [ ] ورودی اعتبارسنجی‌شده، با پیام‌های راهنما وقتی اشتباه است
- [ ] داده‌ای که از فایل خوانده یا در فایل نوشته می‌شود
- [ ] یک `README.md` که توضیح می‌دهد چه می‌کند و چطور اجرا می‌شود

مورد آخر از آنچه فکر می‌کنید ارزشمندتر است. تفاوت بین کد و پروژه همین است، و همین عادت است که کار شما را یک سال بعد برای خودتان خوانا می‌کند.

## نکات کلیدی

- دوره عمداً از پایین به بالا چیده شد: سخت‌افزار، بعد داده، بعد تفکر، بعد نحو، بعد مهندسی.
- اکنون می‌توانید یک برنامه کوچک کامل را بنویسید، اشکال‌زدایی کنید، سازماندهی کنید و داده‌اش را ماندگار کنید.
- یک پروژه کوچک تمام‌شده بیشتر از یک پروژه بزرگ ناتمام آموزش می‌دهد.
- مستندسازی کارتان بخشی از کار است، نه کار اضافه.
- گام بعدی را چیزی تعیین می‌کند که دوستش دارید، نه چیزی که پرزرق‌وبرق به نظر می‌رسد.

## تأمل پایانی

پیش از رفتن، یک صفحه بنویسید که به این پرسش‌ها پاسخ دهد:

۱. سخت‌ترین مفهوم کدام بود و چه چیزی بالاخره جا انداخت؟
۲. کدام جلسه را به دوستی می‌دهید که امروز شروع کرده؟
۳. کوچک‌ترین برنامه‌ای که امروز می‌توانید بنویسید و در ابتدای ماژول ۴ نمی‌توانستید چیست؟
۴. قدم بعدی چه می‌خواهید بسازید؟

پرسش ۳ معیار واقعی دوره است. اگر بتوانید چیز مشخصی نام ببرید، یاد گرفته‌اید.
