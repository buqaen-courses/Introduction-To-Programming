# جلسه ۲۰: سازماندهی کد، ماژول‌ها و یک برنامه کوچک چندفایلی

## مرور جلسه

یک فایل تا وقتی جواب نداد کار می‌کند. جایی برنامه از نقطه‌ای بزرگ می‌شود که دیگر نمی‌توانید چیزی در آن پیدا کنید، و پاسخ طبیعی تقسیم آن بین چند فایل است. این جلسه ماژول‌های پایتون را پوشش می‌دهد: ساختن ماژول، سه روش import کردن از آن، اینکه چرا `if __name__ == "__main__":` وجود دارد، و چطور یک پروژه کوچک را طوری بچینید که هر فایل یک کار داشته باشد.

## اهداف یادگیری کلیدی

در پایان این جلسه می‌توانید:

- **بسازید** یک ماژول و از آن import کنید
- **تفکیک کنید** `import x`، `from x import y` و `from x import y as z`
- **توضیح دهید** چرا `if __name__ == "__main__":` از نقطه ورود یک فایل محافظت می‌کند
- **سازماندهی کنید** یک پروژه در چیدمانی منطقی فایل‌ها
- **به‌کار ببرید** ماژول‌های کتابخانه استاندارد به‌جای بازنویسی آن‌ها
- **پرهیز کنید** از تله import حلقوی

## ماژول فقط یک فایل py است

نحو خاصی وجود ندارد. ماژول یک فایل پایتون است، و هرچه در سطح بالای آن تعریف کنید برای importerها در دسترس می‌شود:

```python
# utils.py
def add(a, b):
    return a + b

TAX_RATE = 0.09
```

```python
# main.py
import utils
print(utils.add(2, 3))        # 5
print(utils.TAX_RATE)         # 0.09
```

## سه روش import

```
    import utils
        → from utils.add(...) استفاده کنید
        → مشخص است هر چیز از کجا آمده

    from utils import add
        → از add(...) استفاده کنید
        → کوتاه‌تر، ولی اگر دو ماژول add داشته باشند مبهم است

    from utils import add as sum_two
        → از sum_two(...) استفاده کنید
        → برای تغییر نام در حالت تداخل

    from utils import *          <- از این پرهیز کنید
        → فضای نام شما را آلوده می‌کند
        → پنهان می‌کند نام‌ها از کجا آمده‌اند
```

توصیه کلی: بالای فایل `import module` را ترجیح دهید. وابستگی را آشکار می‌کند و از تداخل نام‌ها جلوگیری می‌کند.

## نگهبان __main__

این تا وقتی پروژه ننویسید که شکل تشریفاتی به نظر می‌رسد:

```python
# main.py
from calc import add

def main():
    print(add(1, 2))

if __name__ == "__main__":
    main()
```

وقتی `main.py` را مستقیم اجرا می‌کنید، `__name__` برابر `"__main__"` است و `main()` اجرا می‌شود. وقتی `main.py` را فایل دیگری *import* می‌کند، `__name__` برابر `"main"` است و آن بلوک رد می‌شود. بدون این نگهبان، import کردن یک فایل همه‌چیز داخلش را اجرا می‌کند، و به همین دلیل فایلی با `print("loading...")` در سطح بالا، هر بار که چیزی آن را import کند آن را چاپ می‌کند.

## چیدمان منطقی یک پروژه

برای یک برنامه کوچک، همین کافی است:

```
    myapp/
    ├── main.py          نقطه ورود، تعامل با کاربر، main()
    ├── calc.py          منطق محاسبه
    ├── storage.py       خواندن و نوشتن فایل
    └── data/
        └── sample.txt   داده، بیرون از کد نگه داشته شده
```

دو قاعده که جلوی درهم‌تنیدگی را می‌گیرد:

- **بدون import حلقوی.** اگر `a.py`، `b.py` را import کند و `b.py` هم `a.py` را، شکست می‌خورد. اگر کد مشترک لازم دارید، در فایل سومی بگذارید که هر دو آن را import کنند.
- **`main.py` import می‌کند؛ بقیه `main.py` را import نکنند.** وابستگی‌ها مثل پیکان یک‌طرفه‌اند.

## کتابخانه استاندارد

این‌ها را نیازی نیست خودتان بنویسید:

```
    random        اعداد تصادفی، انتخاب، درهم‌ریختن
    datetime      تاریخ و زمان
    math          ریشه دوم، پی، کف و سقف
    json          خواندن و نوشتن JSON
    collections   Counter، defaultdict، namedtuple
    pathlib       مدیریت مدرن مسیر
```

```python
import random
from datetime import datetime

print(datetime.now().strftime("%Y-%m-%d %H:%M"))
print(random.choice(["Ali", "Sara", "Reza"]))
```

اگر در آستانه نوشتن یک تابع کمکی هستید، اول ببینید کتابخانه استاندارد آن را دارد یا نه. برای پروژه پردازش فایل این دوره، `json` تقریباً همیشه بهتر از قالب کاماجدای دست‌ساز است.

## مفاهیم اصلی

- **ماژول یک فایل `.py` است**؛ نحو خاصی ندارد
- **`import x`، `from x import y`، `as`** سه سبک هستند
- **از `from x import *` پرهیز کنید**؛ منشأ نام‌ها را پنهان می‌کند
- **`if __name__ == "__main__":`** اجرا شدن را از import شدن جدا می‌کند
- **وابستگی‌ها یک‌طرفه‌اند**؛ چرخه در زمان import شکست می‌خورد
- **`main.py` import می‌کند، بقیه فایل‌ها `main.py` را import نمی‌کنند**
- **پیش از نوشتن یک تابع کمکی، کتابخانه استاندارد را بررسی کنید**

## اشتباهات رایج مبتدی

| اشتباه | پیامد |
|--------|-------|
| کد سطح بالا بدون نگهبان `__main__` | با هر import دوباره اجرا می‌شود |
| `from x import *` | تداخل نام‌هایی که نمی‌توانید ردیابی کنید |
| نام‌گذاری فایل `random.py` یا `math.py` | کتابخانه استاندارد را می‌پوشاند؛ خطاهای گیج‌کننده |
| import حلقوی بین ماژول‌ها | در زمان شروع `ImportError` |
| import کردن بعد از شروع کد | مجاز ولی گیج‌کننده. import‌ها بالای فایل می‌روند |
| گذاشتن همه منطق در `main.py` | تقسیم فایل بعداً و دقیقاً وقتی دردناک‌ترین است انجام می‌شود |

## فعالیت‌های کارگاه

۱. **پروژه دو فایلی.** یکی از اسکریپت‌های قبلی‌تان را بشکنید: توابع در یک فایل، تعامل با کاربر در فایل دیگر، و `main.py` که این دو را به هم وصل می‌کند.
۲. **کتابخانه کمکی.** دونفره، یک `utils.py` با پنج تابع کمکی بسازید. فایل‌ها را با هم رد و بدل کنید و در یک اسکریپت راه‌انداز از ماژول همدیگر استفاده کنید.
۳. **بازآرایی.** بلندترین برنامه‌تان را بردارید و به دست‌کم سه فایل با کارهای متمایز بشکنید. به هرکدام نگهبان `__main__` اضافه کنید.
۴. **چرخه عمدی.** دو ماژول بسازید که همدیگر را import کنند. `ImportError` را ببینید. بعد چرخه را با یک ماژول مشترک بشکنید.

## تکالیف

- **تمرین ماژول**: ماژولی از توابع ریاضی بسازید (`add`، `subtract`، `multiply`، `divide` با مدیریت تقسیم بر صفر، `power`، `factorial`) و اسکریپتی که از آن‌ها استفاده کند.
- **چیدمان پوشه**: از فایل‌های پروژه‌تان نمودار بکشید، بگویید هرکدام مسئول چه چیزی است، و جهت هر import را علامت بزنید.
- **کتابخانه استاندارد**: سه ماژول از کتابخانه استاندارد انتخاب کنید، از هرکدام در اسکریپت کوتاهی استفاده کنید، و دو جمله درباره اینکه چه چیزی را جایگزین می‌کنند بنویسید.
- **تأمل**: نوشته‌ای کوتاه درباره اینکه چرا سازماندهی کد مهم است، از منظر هزینه‌ای که وقتی انجامش ندهید می‌دهید.

## نکات کلیدی

- ماژول فقط یک فایل است. تقسیم برنامه، بعد از فهمیدن دلیلش کاری مکانیکی است.
- `if __name__ == "__main__":` همان چیزی است که نمی‌گذارد import کردن همه‌چیز را اجرا کند.
- importهای یک‌طرفه پروژه را قابل اشکال‌زدایی نگه می‌دارند.
- کتابخانه استاندارد بیش از آنچه فکر می‌کنید مسئله حل کرده است.
- چیدمان فایل‌ها را پیش از بزرگ شدن کد تصمیم بگیرید، نه بعدش.
