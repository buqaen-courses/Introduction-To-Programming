# جلسه ۱۲: ورودی، خروجی، عبارت‌ها و عملگرها

## مرور جلسه

حالا متغیرهایی داریم که مقدار نگه می‌دارند. این جلسه برنامه‌ها را تعاملی می‌کند: از کاربر چیزی بخوان، با آن چیزی حساب کن، نتیجه را چاپ کن. در این مسیر عملگرهای حسابی و مقایسه‌ای را می‌سازیم و مهم‌تر از همه قواعد تقدم را که تعیین می‌کند `2 + 3 * 4` واقعاً چه معنایی دارد. اشتباه گرفتن تقدم، شایع‌ترین منبع باگ‌های خاموش منطقی در پایتون ابتدایی است، پس این جلسه واقعاً روی آن وقت می‌گذارد.

## اهداف یادگیری کلیدی

در پایان این جلسه می‌توانید:

- **بخوانید** ورودی با `input()` و آن را به نوع درست تبدیل کنید
- **چاپ کنید** مقادیر و خروجی را خوانا قالب‌بندی کنید
- **به‌کار ببرید** عملگرهای حسابی از جمله `//`، `%` و `**`
- **به‌کار ببرید** عملگرهای مقایسه‌ای برای ساختن مقدار boolean
- **درست اعمال کنید** تقدم عملگرها و آگاهانه از پرانتز استفاده کنید
- **بسازید** برنامه‌های کوچکی که ورودی، پردازش و خروجی را ترکیب می‌کنند

## ‌input() همیشه رشته برمی‌گرداند

این یک واقعیت، بیشتر اشتباهات هفته اول را می‌سازد:

```python
age = input("How old are you? ")
print(type(age))    # <class 'str'>  -- همیشه
```

پس این کد شکست می‌خورد:

```python
print(age + 1)      # TypeError
```

و این کار می‌کند:

```python
age = int(input("How old are you? "))
print(age + 1)
```

فراخوانی `input()` را در تبدیلی که نیاز دارید بپیچید. این پرتکرارترین خطی است که در این دوره خواهید نوشت.

## عملگرها

```
    ARITHMETIC                    COMPARISON
    ---------                     ----------
    +   addition                  ==   equal
    -   subtraction               !=   not equal
    *   multiplication            <    less than
    /   true division (→ float)   >    greater than
    //  floor division (no rem.)  <=   less or equal
    %   remainder / modulo        >=   greater or equal
    **  power

    LOGICAL (detailed in Session 13)
    --------
    and   or   not
```

سه مورد از این‌ها ارزش توضیح دارند:

- `/` همیشه float می‌دهد. `10 / 2` می‌شود `5.0`، نه `5`.
- `//` رو به پایین گرد می‌کند و باقی‌مانده را دور می‌اندازد. `10 // 3` می‌شود `3`.
- `%` فقط باقی‌مانده را می‌دهد. `10 % 3` می‌شود `1`.

دو تای آخر روش به‌دست‌آوردن «چند جعبی کامل» و «چند تا باقی مانده» هستند.

## تقدم: چه چیزی اول محاسبه می‌شود

پایتون با ترتیبی تعریف‌شده ارزیابی می‌کند. از بالا به پایین:

```
    1. ()                      پرانتز، بالاترین سطح، و همیشه صریح
    2. **                      توان
    3. +x  -x                  علامت یکانی
    4. *  /  //  %             ضرب و تقسیم
    5. +  -                    جمع و تفریق
    6. <  <=  >  >=  ==  !=    مقایسه
    7. not                     not منطقی
    8. and                     and منطقی
    9. or                      or منطقی
```

پس:

```python
2 + 3 * 4        # 14، نه 20  (اول ضرب)
(2 + 3) * 4      # 20
```

همین قاعده بر مقایسه هم حاکم است:

```python
1 + 2 == 3       # True  (مقایسه بعد از جمع انجام می‌شود)
1 + 2 == 4       # False
```

## وقتی تقدم غافلگیرتان می‌کند

ضرب و تقسیم **از چپ به راست** هستند، و جمع و تفریق هم همین‌طور. نکته غافلگیرکننده این است که این‌ها *گروه‌های متفاوتی* هستند:

```python
100 / 10 / 2      # 5.0    ( (100/10) / 2 )
2 ** 3 ** 2       # 512    از راست به چپ! (2 ** (3 ** 2) )
```

خط دوم حتی برنامه‌نویسان باتجربه را هم غافلگیر می‌کند. هر وقت ترتیب مورد نظر برای خواننده روشن نبود، پرانتز بگذارید. وضوح بر کوتاهی مقدم است.

## مفاهیم اصلی

- **`input()` رشته برمی‌گرداند**، همیشه
- **تبدیل نوع**: `input()` را در `int()` یا `float()` بپیچید
- **عملگرهای حسابی**: `+ - * / // % **`
- **عملگرهای مقایسه‌ای**: مقدار `True` یا `False` می‌سازند
- **تقدم**: ترتیبی که عملیات به آن ترتیب ارزیابی می‌شوند
- **شرکت‌پذیری**: از چپ به راست برای `* /` و `+ -`، و از راست به چپ برای `**`
- **پرانتز**: روشن‌ترین ابزار شما برای از بین بردن ابهام

## اشتباهات رایج مبتدی

| اشتباه | نتیجه |
|--------|-------|
| استفاده مستقیم از `input()` در حساب | `TypeError` |
| استفاده از `=` به‌جای `==` | به‌جای مقایسه، boolean انتساب می‌دهد |
| فرض اینکه `/` عدد صحیح می‌دهد | `5.0` جایی که `5` انتظار داشتید |
| اشتباه گرفتن `//` و `/` | نتیجه غلط، بدون پیام خطا |
| فراموشی اینکه `**` از راست به چپ است | `2 ** 3 ** 2` می‌شود ۵۱۲، نه ۶۴ |
| نوشتن `1 < x < 10` بدون فکر به `and` | به‌درستی نوشته شده؛ فقط بدانید `and` ضعیف‌تر از `==` پیوند می‌خورد |

## فعالیت‌های کارگاه

۱. **محاسبه‌گر سن.** سال جاری و سال تولد کاربر را بپرسید. سن او را چاپ کنید و سن او در سال آینده را هم. تبدیل را درست انجام دهید.
۲. **محاسبه‌گر مستطیل.** عرض و طول را بپرسید. مساحت و محیط را چاپ کنید، هرکدام در خط خودش با یک برچسب.
۳. **کدام بزرگ‌تر است؟** دو عدد بگیرید و چاپ کنید کدام بزرگ‌تر است. بعد برنامه را طوری گسترش دهید که حالت برابر بودن را هم مدیریت کند.
۴. **پیش‌بینی کن، بعد اجرا کن.** پنج عبارت از روی تخته بردارید، نتیجه را بنویسید، بعد با پایتون بررسی کنید. هر موردی را که از دست دادید، دوباره با دست دنبال کنید.

## تکالیف

- **محاسبه‌گرهای کوچک**: تبدیل ارز، تبدیل دما، و تبدیل ثانیه به ساعت و دقیقه.
- **معماهای عبارتی**: پانزده عبارت برای ساده‌سازی و محاسبه. روند کار خود را بنویسید، از جمله اینکه کجا تقدم را اعمال کردید.
- **داستان ورودی/خروجی**: برنامه کوتاهی بنویسید که سه پرسش بپرسد و به هر پاسخ واکنش متفاوتی نشان دهد.
- **تأمل**: سه جمله درباره اینکه چرا رشته برگرداندن از `input()` یک تصمیم طراحی است نه یک نقص.

## نکات کلیدی

- `input()` به شما رشته می‌دهد؛ پیش از حساب تبدیل کنید.
- `/` ممیز می‌دهد، `//` و `%` خارج‌القسمت و باقی‌مانده را جدا می‌کنند.
- تقدم ترتیب را تعیین می‌کند؛ پرانتز ابهام را کامل از بین می‌برد.
- `**` از راست به چپ است، برخلاف `* /` و `+ -`.
- پرانتز شلوغی نیست. مستندسازی است.
