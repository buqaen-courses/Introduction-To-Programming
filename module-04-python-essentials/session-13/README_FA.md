# جلسه ۱۳: تصمیم‌گیری با if، elif و else

## مرور جلسه

تا اینجا هر برنامه‌ای که نوشتیم هر بار یکسان اجرا می‌شد. این جلسه جایی است که برنامه بر اساس داده‌اش رفتار متفاوتی نشان می‌دهد. ساختار کنترلی selection از جلسه ۹ را به پایتون ترجمه می‌کنیم، با منطق boolean پایتون (`and`، `or`، `not`) و قواعد درستی‌سنجی آن آشنا می‌شویم، و سپس شرط‌ها را تودرتو می‌کنیم تا تصمیم‌هایی را مدیریت کنیم که به تصمیم‌های دیگر وابسته‌اند.

## اهداف یادگیری کلیدی

در پایان این جلسه می‌توانید:

- **بنویسید** دستورهای `if`، `if/else` و `if/elif/else` را درست
- **به‌کار ببرید** عملگرهای مقایسه‌ای برای ساخت شرط
- **ترکیب کنید** شرط‌ها را با `and`، `or` و `not`
- **پیش‌بینی کنید** برای یک ورودی مشخص کدام شاخه اجرا می‌شود
- **تودرتو کنید** شرط‌ها و بدانید کِی باید متوقف شوید
- **دیباگ کنید** خطاهای تورفتگی و منطق در شرط‌ها

## از دو راهی تا چند راهی

شکل پایه، و بعد بسط آن:

```python
# یک راه
if score >= 60:
    print("Pass")

# دو راه
if score >= 60:
    print("Pass")
else:
    print("Fail")

# چند راه
if score >= 90:
    print("A")
elif score >= 80:
    print("B")
elif score >= 70:
    print("C")
else:
    print("F")
```

`elif` کوتاه‌شدهٔ «else if» است. تنها **اولین** شاخهٔ منطبق اجرا می‌شود، بعد پایتون بقیه را رد می‌کند. به همین دلیل ترتیب مهم است: سخت‌گیرانه‌ترین شرط را اول بگذارید، وگرنه نمره ۹۵ با `>= 60` جور درمی‌آید و هرگز به شاخه `A` نمی‌رسد.

## تورفتگی در پایتون تصادفی نیست

تورفتگی بعد از `:` سبک نیست. نحو زبان است و بلوک را تعریف می‌کند.

```python
if score >= 60:
    print("Pass")
    print("Congratulations")   # همان بلوک، هر دو اجرا می‌شوند
print("Done")                  # بلوک دیگر، همیشه اجرا می‌شود
```

ترکیب تب و فاصله، یا تورفتگی متفاوت برای یک خط از یک بلوک، یا `IndentationError` می‌دهد یا بی‌صدا تعیین می‌کند کدام خطوط داخل بلوک هستند.

## درستی‌سنجی: قواعد پایتون

شرط‌ها لازم نیست `True` یا `False` باشند. هر مقداری می‌تواند شرط باشد و پایتون با این قواعد تصمیم می‌گیرد:

```
    FALSY  (treated as False)              TRUTHY  (treated as True)

    0                zero                  1            nonzero number
    0.0              zero float            -1           any nonzero number
    ""              empty string          "hi"         nonempty string
    ''              empty string          " "          whitespace string
    []              empty list            [0]          nonempty list
    {}              empty dict            {"k": None}  dict with a None value
    None            no value

    NOTE:  [0] is TRUTHY. A list containing zero is still a list,
           and the list is not empty.
```

سطر آخر غافلگیرکننده است. `[0]` لیستی خالی‌نبوده است، پس درست‌سنج است، هرچند آنچه داخلش است نادرست‌سنج.

## ترکیب شرط‌ها

```
    and    هر دو طرف باید درست باشد
    or     حداقل یک طرف باید درست باشد
    not    ارزش درستی را برمی‌گرداند

    age >= 18 and has_id          هر دو لازم است
    score > 90 or bonus > 50      هر کدام کافی است
    not is_expired               معکوس می‌کند
```

یک باگ رایج، نوشتن `18 <= age <= 65` است که درست و معتبر است، در برابر `18 <= age and age <= 65` که همان نتیجه را دارد ولی خواندنش راحت‌تر است. هر دو کار می‌کنند. آنی را انتخاب کنید که با آنچه بلند می‌خوانید هم‌خوان است.

## مفاهیم اصلی

- **`if` یک بلوک را وقتی شرط درست است اجرا می‌کند**
- **`else` بقیه را می‌گیرد**
- **`elif` گزینه‌های جایگزین می‌سازد؛ تنها اولین تطبیق اجرا می‌شود**
- **بلوک با تورفتگی تعریف می‌شود**، نه با آکولاد
- **درستی‌سنجی**: هر مقداری می‌تواند شرط باشد
- **`and`، `or`، `not`** شرط‌ها را ترکیب و نفی می‌کنند
- **نگهبان‌ها**: بررسی و خروج زودهنگام معمولاً از تودرتو کردن خواناتر است

## اشتباهات رایج مبتدی

| اشتباه | چرا شکست می‌خورد |
|--------|------------------|
| فراموشی دو نقطه بعد از `if` | `SyntaxError` |
| تورفتگی ناسازگار داخل بلوک | `IndentationError`، یا بلوکی که زودتر تمام می‌شود |
| استفاده از `=` به‌جای `==` | مقدار `True` را انتساب می‌دهد؛ شرط در نتیجه درست‌سنج است |
| گذاشتن شرط ضعیف‌تر اول در زنجیره `elif` | شاخه‌های بعدی هرگز اجرا نمی‌شوند |
| نوشتن `if x == True:` | کار می‌کند، ولی `if x:` خواناتر است |
| فرض درستی‌سنجی `[0]` | درست‌سنج است. لیست خالی نادرست‌سنج است، لیستی که صفر دارد نه. |

## فعالیت‌های کارگاه

۱. **بررسی قبولی/مردودی.** یک نمره بخوانید و `Pass` یا `Fail` چاپ کنید. بعد گسترش دهید تا `Excellent`، `Good`، `Needs Work` و `Fail` را تشخیص دهد.
۲. **علامت عدد.** چاپ کنید که ورودی مثبت است، منفی است یا صفر. این تمرین شما را مجبور می‌کند به حالت صفر فکر کنید به‌جای فراموش کردنش.
۳. **منطق تخفیف.** زنجیره `if/elif` بنویسید: زیر ۵۰ بدون تخفیف، زیر ۱۰۰ پنج درصد، زیر ۲۰۰ ده درصد، بالای آن پانزده درصد.
۴. **شکار باگ عمدی.** برنامه‌ها را با همکلاسی‌تان عوض کنید. بدون اجرا سه باگ در کد شرطی او پیدا کنید. بعد اجرا کنید و ببینید چندتایش را گرفتید.

## تکالیف

- **تمرین شرط**: پیام روز و شب، واجد شرایط بودن برای رأی دادن، و تشخیص سال کبیسه.
- **پیش‌بینی شاخه**: با توجه به پنج قطعه‌کد و ورودی‌هایشان، بنویسید کدام شاخه اجرا می‌شود. بعد اجرا کنید.
- **بازنویسی شبه‌کد**: سه الگوریتم تصمیم از [جلسه ۹](../../module-03-algorithmic-thinking/session-09/README_FA.md) را به شرط‌های پایتون تبدیل کنید.
- **بازآرایی**: یک شرط تودرتو که در کارگاه نوشتید با نگهبان‌ها بازنویسی کنید. ببینید کدام خواناتر است.

## نکات کلیدی

- تورفتگی بلوک را تعریف می‌کند؛ پایتون آکولاد ندارد.
- تنها اولین `elif` منطبق اجرا می‌شود، پس شرط‌ها را از سخت به آسان بچینید.
- هر مقداری می‌تواند شرط باشد؛ پایتون با درستی‌سنجی تصمیم می‌گیرد.
- `[0]` درست‌سنج است. لیست خالی نادرست‌سنج است.
- شرط تودرتو اشکالی ندارد، ولی زنجیره تخت `elif` معمولاً خواناتر است.

## اتصال به جلسه بعد
